# W890 0603 HII 更新流程

REA 已核对原 AMITSE 的 `40094 / 3FED4 / 4244C / 426CC / 429C4 / 42B78`，并保留十份有效查询证据。四处原 CALL 的字节和目的地址独立核对一致；其中两个调用点的 Ghidra 函数归属查询返回“未纳入函数”，没有将它解释成不存在调用。

原 `40094` 会先整理通知队列，按实际 HII 处理页面新增、删除或替换，也可能按当前 SendForm 的 HII 列表筛选。删除处理会使原生描述符暂时带 `FFFF` 标记，回调后的刷新还会清理旧缓存和这些标记。因此，旧实验桥只允许空队列，会妨碍正常固件功能。

当前方案保留原厂队列处理、原调用顺序和返回值。新增密码锁负责作废自身的旧页面证明，并在下一次受保护操作前重新核对当前 HII 和原生描述符。普通设备页面更新不应自动撤销整个 BIOS 会话；未知的主设置包更改仍须使保护身份失效。

十个真实原指令用例覆盖空队列、链表排空、按 HII 筛选、未匹配节点保留、FreePool 错误返回，以及三种业务处理前的停止边界。七个用例执行到原函数返回，三个停在尚未执行的原帮助函数入口。测试的队列、内存分配和唯一 FreePool 服务是明确模型，没有把未知业务函数替换成成功，也没有声称整次刷新或 GUI 已模拟完成。

第一次受限执行在 Ghidra 完成导入后无法连通本地分析桥，600 秒到期并正常关闭；失败证据保留。随后允许本机回环连接的执行沿用同一原件和超时预算，查询、证据导出与关闭成功，未关闭任何引擎校验。

这份证据支持缩小干预范围，尚不是整合后的密码锁或 BIOS 映像。代次管理、其他菜单识别和正常退出的组合验证分别在相邻组件中进行。
