# HERO IPMI B2c：处理启动时的 KCS 错误状态

2026-10-14 的 B2b 实测在第一次读取时得到 **C1**，随后按设计停止。C1 表示 KCS 处于 ERROR 状态、输入缓冲空、输出缓冲有数据；它不是 IPMI 命令的返回码。本次没有发送 Get Device ID、I 或 F，退出时 PCI 设置已恢复。用户已重启过 BMC，网页可以打开，因此下一步直接检查主机侧 KCS 恢复。

B2c 在启动时先只读观察。连续三次 00 便读取基线；连续三次 C0/C1 才提供单独的 **K**。按 K 后至多执行一次标准 GET_STATUS/ABORT 握手，取得接口错误状态字节，确认回到空闲后才继续。K 会终止这个 KCS 通道上未完成的交换；不是 BMC 重启，也不刷写 BIOS/BMC。恢复路径尚未在目标机验证。

## 本次运行

1. 保留已有日志，把本包 `USB` **里面**的 `EFI` 和 `HERO-PROBE-USB.TAG` 一起更新到 FAT32 U 盘根目录。启动确认标题 **HERO IPMI FAN B2c**。继续使用当前 BIOS 3107。
2. 按屏幕提示 **E/P**，观察启动状态。若提示 **K**，按一次 K。若直接读出基线，则不需要 K；若自动停止，保留日志并退出。
3. 成功读取基线后，按屏幕实际提供的选项继续：先提供 **I** 就执行一次 I，再看是否提供 F；已有 **F** 就可执行原定的 CHA_FAN1 实验。没有提示时不要盲按 I/F。
4. F 完成后等约 **30 秒**，按 **R** 再读取一次，同时查看 BMC 网页的 `MB_CHA_FAN1`。先前 BIOS 截图的 2884 RPM 只是历史参考，需要同时期读数才能核实实际对应关系。
5. 按 **Q** 结束采样，日志关闭后再按 **Q** 返回启动菜单。若自动停止，日志关闭后按一次 Q。提供本次新生成的 `HEROIPMI-xxx.TXT`；若运行了 F，再补充网页读数。

如只测试通信，读完基线后直接 Q 即可。I/F 与此前版本作用相同，会改变 BMC 的初始化、转速映射或扫描状态；**Q 不撤销这些修改**。K、I、F 均各有独立入口，恢复成功不会自动执行 I/F。

## 恢复边界与日志

- K 只在尚未发过任何 IPMI 请求、尚未读过 KCS 数据或写过 KCS、启动连续三个 C0/C1 的情况下提供。普通读/写进行中、IBF 忙、attention、FF 等状态不提供 K。
- K 要求 HERO BIOS 3107、已验证的 ASPEED 1A03:2402 revision 01、位置 `0000:04:01.0`、原有 BAR 和可写日志；重新检查没有 AMI IPMI transport 驱动。恢复前还无法取得 Get Device ID 指纹；恢复后的基线仍按原有指纹限制 I/F。
- 记录 `PREEXISTING_OUTPUT`，有 OBF 才读取残留字节。该字节不能直接解释为握手返回的错误码。
- 恢复只按顺序写 `COMMAND 60`、`DATA 00`、`DATA 68`。每次写前检查 IBF 已清、状态正确、OBF 已处理；每次数据读前确认 OBF 已置位。
- 握手的 `ERROR_CODE` 原样记入日志，和状态寄存器值分开。它不一定能追溯最初故障原因，例如 `01` 可能只是报告本次 Abort 终止了交换；数据字节 FF 也不等同于状态寄存器 FF。
- 整个恢复共用最多 1000 次状态轮询，等待间隔 10 ms，约 10 秒加 PCI/日志开销；异常、PCI 改变、I/O/日志/等待失败均停止。最多一轮握手，不重发，不自动重启 BMC。
- 握手必须经历 WRITE、READ、IDLE 并取得最终 dummy，再重新观察三个连续 00，才首次发送 Get Device ID。`KCS_RECOVERY_HANDSHAKE_COMPLETE` 只表示握手完成；`GET_DEVICE_ID_OK` 才证明正常请求有响应。
- E/P 的初始等待仍最多 31 次、间隔 1 秒。FF 可以在窗口中继续观察；C0/C1 连续次数被其他值打断后重新计数。恢复后的等待不再提供第二次 K。
- 所有已开始的正常请求仍保持失败停止、不重放。正常和已处理错误路径尝试恢复 PCI Command 内存位并读回；死机、断电或设备身份变化时不能保证恢复。

## 进度与验证范围

B1 已在实机取得 4 项温度和 4 项电压可用读数；风扇可用读数、开机自动初始化、BIOS 集成仍未完成。003/004 和本次 B2b 均未进入 F，因此当前没有新的风扇实测结论。

最终 EFI 已通过 **222 个离线场景**，记录在 `verification.json`：原有基线/I/F/启动等待 148 项，以及本版 KCS 恢复、拒绝、异常、超时、日志与 PCI 变化、按键隔离等 74 项。设备由模拟器提供，部分传感器回复重放以前实机日志；**这些测试不证明目标硬件恢复成功，也不证明风扇值正确**。`example-MOCK-*` 全为离线模拟日志。

包内源码和脚本依赖现有 BIOS 工作区工具与历史证据。只有本程序的 USB EFI，无 BIOS/BMC 镜像或供体 DXE；现有 R1 CAP 的已知依赖问题并未因此修复。
