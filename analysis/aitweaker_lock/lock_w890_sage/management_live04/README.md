# W890E-SAGE SE 0603 management publication component 04

This implements the actual HII publisher and ConfigAccess bridge for the independent password core. It is a review component, **not a flashable BIOS or an auto-installing driver**. Its EFI entry returns `EFI_UNSUPPORTED` without publishing anything. Frozen `password`, `password_runtime02` and `password_recovery03` were not edited.

## Implemented behavior

- Exact Setup and AMITSE loaded-image shapes, FV file GUIDs and original `.text` SHA-256; Setup HII package GUID `899407D7-99FE-43D8-9A21-79EC328CAC21`; official forms SHA `0111abd4e9914a32b865fc95af15990687a9d05f984df533c30e028e38cbba2f`.
- Original ConfigAccess Extract/Route/Callback identities `Setup+2240 / +2248 / +2250`. Only the external installer replaces Callback. Extract and Route are never written by this component.
- Bounded, copied patch records match `NO_PATCH` layout: module 0 = AMITSE, module 1 = Setup. Include only executable `.text` records in `MP_BINDING`; the ConfigAccess Callback data pointer is independently checked and must not be passed as a text overlay. Bind requires pristine original bytes. Later checks accept each exact original or exact reviewed installed record and hash the normalized original `.text`; any unknown byte fails. Reviewed patch provenance and transaction phase belong to the installer/observer, not a caller-provided compatibility flag.
- Six allocated strings and three fixed 15-byte ACTION opcodes in Security form `271D`, QuestionIds `FFD0` set/change, `FFD1` clear, `FFD2` verify. All primary UI languages receive each new string through real NewString/SetString and exact GetString readback. Currently the same English wording is used in every language; it is not a translated UI. Duplicate, malformed or keyword languages (`x-UEFI`) stop before mutation.
- Save the complete original exported package before the first string mutation. Verify original strings remain unchanged, the fixed forms insertion is exact, all other packages are preserved, and the complete final export matches the expected bytes.
- Rollback uses the complete original package, verifies its complete export byte for byte, and checks newly allocated string IDs are absent. An unrelated edit to existing strings/forms is not overwritten. Failed, false-success or uncertain updates retain the original snapshot and leave the component closed.
- Pin service method pointers and recheck readable protocol objects after each external service. A lost publication lease, changed identity, substituted method or end-boot event stops further mutation. Cleanup cannot force calls after the lease expires or after ExitBootServices.
- Original nonmanagement callbacks forward the original six arguments, output storage and status. Management callbacks require type 10 (the original browser's ACTION type), action 0 or 1, and the native authority ticket. Only action 0 interacts; action 1 acknowledges. Unknown managed IDs cannot fall through to the original callback. The bridge calls actual frozen Runtime02, including masked input and saved-screen restoration.

## Required load order and lifecycle

1. Use the EFI-entry system table as the bootstrap trust anchor. Initialize the native observer on pristine original loaded modules/HII and construct the reviewed installer patch list.
2. Populate `MP_BINDING` from independently discovered observer identity and actual HII String protocol. Call `mp_bind` before modifying original bytes; it only verifies and captures identity, without HII writes.
3. Prepare the observer with exact module overlays and actual compiled consumer call windows. The external transaction installs the reviewed original native detours and changes only original ConfigAccess Callback to `mp_callback`.
4. Set `NO_INSTALL.publish = mp_native_publish` and `publisher = state`. This actual compiled EFI_STATUS adapter calls `mp_publish(state, ticket)` inside the genuine first native entry wrapper, before the original entry executes and before native application/descriptors/SendForm context exist. A positive MP_RESULT failure is never misread as EFI success. Its authority callbacks are `no_publication_validate`, `no_publication_finished` and `no_restoration_finished`. A generic `idle=true`, loop depth zero, or a late BootOverride application does not authorize publication.
5. On success the observer independently recreates the 45-byte insertion from official forms and the six actual allocated IDs. Publication completion does not consume the transaction lease; the overall installer owns completion. HII notifications must be registered separately for NEW=1, REMOVE=2 and ADD=8. In real OVMF, registering the combined value 11 returns success but never dispatches notifications because EDK II compares the notification type for equality.
6. On failure, rollback the complete package while the bridge remains installed and the same valid cold window exists. Only after verified restoration may the installer restore original Callback and module patches, then call `mp_dispose`. `MP_DIRTY` or `MP_ENDED` is not permission to resume the original browser, unload referenced code or force a repair. Preserve resident state and report the failure.
7. Route the actual ExitBootServices event to both `mp_end_boot` and Runtime02/observer revocation before any component can be unloaded. This publisher intentionally does not install its own competing event or mutation hook.

`MP_STATE` contains a 597,466-byte text verification scratch area in addition to transaction state. Allocate it as resident driver-owned global/pool storage using `sizeof(MP_STATE)`, never as a temporary UEFI stack object. The original/exported package snapshots are separate bounded Boot Services allocations. A lost window may intentionally retain those allocations until controlled restart; an unsafe forced cleanup is not treated as recovery.

The management authority validates the original AMITSE callback return `+3E4F0`, native action globals, selected Security control, actual IFR provenance and private active session. Runtime02 operation authorization must match the reviewed private `call_provider` return site plus that live native management ticket. `mp_management_scope` and `mp_provider_caller` are helpers, not independent authority to modify OC variables. The compiled callsite must be re-derived after every combined link; the standalone component's value is in `build/bridge_pe_tests.json`.

## Validation and boundaries

`lab/runs/20261108_024238/result.json`: **114 checks**, actual QEMU TCG/OVMF HII Database and String services, full package export/update/rollback, separately registered synchronous notifications, actual SHA-256, and actual compiled bridge → Runtime02 → GOP/text/input UI → Escape cancellation. The lab uses inert copies of verified original module bytes, explicit simulated native window/session authority and an Escape-producing input shim. The native ASUS browser does not execute in this lab. All lab password/OC SetVariable attempts are counted and denied; the final count is zero.

Faults include partial NewString/SetString/GetString failures, fake successful publication/rollback, update-then-error, lost window, altered ConfigAccess, substituted HII method, duplicate languages, rejected action/type, exact allowed module overlay, a byte outside the overlay, unrelated original string changes, and end-boot revocation. Added string removal and complete package restoration use the actual OVMF services.

`build/bridge_pe_tests.json`: **20 checks**, actual standalone EFI instruction execution. This verifies original callback argument/output/status preservation, untouched Extract/Route, closed unpublished management IDs, identity substitutions, method pointer failures, exact compiled provider callsite and end-boot denial. UEFI identity services and original ASUS callback are explicit models; SHA-256 is a Python oracle in this harness. The OVMF lab separately executes the real SHA code.

The lab's keyboard cancellation establishes no permission to set a password on the physical machine. Clear still writes Runtime02's disabled record format, whose independent recovery authority is a separate unresolved deployment requirement. This component neither bypasses capsule verification nor creates a vendor-signed BIOS.

`build/observer_chain_tests.json`: **8 composed instruction tests** connect the actual native observer DLL, actual MP04 and Runtime02. No boolean native owner callback is supplied to Runtime02. The original AMITSE entry/loop prologues and original ConfigAccess indirect CALL at `3E4ED` execute; the observer validates the private frame/session, return `3E4F0`, native globals and selected Security control with canonical IFR/raw-descriptor provenance. Accepted ACTION acknowledgement and masked-UI Escape cancellation pass; forged descriptors, wrong action type, late application state, foreign HII notifications and false-success publication are rejected. The native browser body/application construction and UEFI services are explicit fixtures; SHA/KDF and basic memory primitives use named Python oracles for tractable instruction execution. This is a composed offline proof, not physical execution of the full ASUS browser. Refused early attempts and their fixture corrections are preserved in `build/observer_chain_*attempt.json`.

Primary API reference used for notification behavior: [EDK II HII Database implementation](https://raw.githubusercontent.com/tianocore/edk2/master/MdeModulePkg/Universal/HiiDatabaseDxe/Database.c). NewString/SetString behavior was cross-checked against [EDK II HII string library](https://raw.githubusercontent.com/tianocore/edk2/master/MdeModulePkg/Library/UefiHiiLib/HiiString.c).

## Reproduction

Run `build.py` to compile the closed component. `lab/run.py` regenerates verified inert fixtures, rebuilds the distinct TCG-only carrier, and runs real OVMF. `verify_bridge_pe.py` executes the standalone component with the declared modeled boundaries. No script connects to BMC, writes a firmware image, or touches physical password/OC variables.
